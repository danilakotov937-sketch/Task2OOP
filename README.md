# Кинг — механика игры (этап 2)

Библиотека классов и консольное приложение для карточной игры «Кинг» (4 игрока, колода из 32 карт).
Механика ничего не печатает: она хранит состояние и рассылает события, а вывод — отдельный слой (`king.cli`).

## Требования и запуск

* Java 21, Maven 3.9+
* Сборка и тесты: `mvn clean test`
* Пакет: `mvn clean package` → `target/king-1.0.jar`
* Документация: `mvn javadoc:javadoc` → `target/site/apidocs`
* Прогон четырёх ботов: `java -jar target/king-1.0.jar demo 42` (42 — зерно генератора)
* Человек (место 0) против трёх ботов: `java -jar target/king-1.0.jar human 42`
  (если русские буквы и масти выводятся «вопросиками» — добавьте `-Dstdout.encoding=UTF-8`)

Один и тот же посев всегда даёт одну и ту же партию.

## Правила, реализованные в модели

* Четыре игрока (места 0–3, ход по часовой стрелке), по 8 карт, 8 взяток в каждой раздаче.
  Карты: 7, 8, 9, 10, В, Д, К, Т четырёх мастей. Старшинство — как перечислено.
* Партия — десять конов подряд, по одной раздаче на кон. Сдающий меняется по кругу, заходит игрок слева от сдающего;
  дальше заходит тот, кто взял предыдущую взятку.
* Обязанность хода в масть: если есть масть захода — нужно ответить в масть. Если масти нет — можно сыграть любую карту
  (бить козырем не обязательно), кроме особого случая «кинг» (см. ниже).
* Взятку берёт старший козырь, а при отсутствии козырей — старшая карта масти захода.

| № | Кон | Очки |
|---|-----|------|
| 1 | Не брать взяток | −2 за взятку |
| 2 | Не брать червей | −2 за каждую червовую карту |
| 3 | Не брать дам | −4 за даму |
| 4 | Не брать королей и валетов | −2 за карту |
| 5 | Не брать две последние | −8 за каждую из 7-й и 8-й взяток |
| 6 | Не брать кинга | −16 за короля червей |
| 7–10 | Брать взятки (четыре кона) | +3 за взятку, есть козырь |

Сумма штрафов (−96) равна сумме наград (+96), поэтому **сумма очков всех игроков после партии равна нулю**.

**Ограничения хода.** В конах 2 и 6 нельзя заходить червой, пока на руке есть карты другой масти. В коне 6, если нет масти
захода, нужно сбросить короля червей. В конах на взятие козырем объявляется масть последней сданной карты
(она достаётся сдающему и видна всем в событии `DealStarted`).

**Итог партии.** Побеждает игрок с наибольшей суммой; при равенстве победителей несколько.

## Структура проекта

```
king.model  — Suit, Rank, Card, Deck, Seats<T>, CardOrder (компараторы), Play, Trick
king.rules  — Contract (интерфейс кона) и его реализации, фабрика Contracts
king.game   — Deal (одна раздача), KingGame (партия), GameEvent/GameListener, GameRunner, IllegalMoveException
king.ai     — PlayerStrategy, PlayerView, RandomStrategy, LowestCardStrategy
king.cli    — Main, ConsoleRenderer, ConsolePlayer (единственный слой с выводом)
```

Ключевые решения:

* **Контракты как интерфейс.** Все отличия конов (очки за взятку, козырь, ограничения захода и сброса) спрятаны в
  `Contract`; `Deal` и `KingGame` ничего не знают о конкретных конах. Новый кон — новый класс без правки движка.
* **События и наблюдатель.** `KingGame` и `Deal` создают `GameEvent` (запись для каждого факта партии) и отдают
  подписчикам `GameListener`; тот же журнал доступен через `KingGame.events()`. Консоль — один из подписчиков.
* **Один генератор.** `Random` передаётся в `KingGame` и в случайных ботов; других источников случайности нет.
* **Компараторы.** `CardOrder.HAND` — порядок карт в руке, `CardOrder.forTrick(led, trump)` — сила карты во взятке.
* **Стратегии игроков.** `PlayerStrategy` получает `PlayerView` (только то, что видит игрок) и возвращает карту.

## Тесты

JUnit 5: правила на граничных ситуациях (ответ в масть, запрет захода червой, обязательный сброс кинга),
подсчёт очков каждого кона, полная партия из зафиксированного посева, воспроизводимость, отсутствие вывода в консоль
во время партии и исключения при недопустимых ходах.
